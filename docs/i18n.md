# Internationalization

## Supported locales

```text
ua (Ukrainian) — default
en (English)
```

Default locale (`ua`) is used for SEO crawlers and first-time visitors without a saved preference.

## URL structure

The application uses **path-based localization**. Every public page is prefixed with the locale code:

```text
/ua
/en
/ua/groups/group-slug
/en/groups/group-slug
```

This structure is required for proper SEO indexing and hreflang support.

## Translation files

```text
app/locales/ua.json
app/locales/en.json
```

Both files must have **identical key structures**.

Example:

```json
{
  "common": {
    "actions": {
      "save": "...",
      "cancel": "..."
    }
  },
  "pages": {
    "groups": {
      "title": "..."
    }
  }
}
```

## Priority system

When resolving the active locale, the system uses this priority order:

1. **User's cookie** (`locale`) — highest priority, persists the user's explicit choice across devices and sessions
2. **URL path** — used when no cookie exists
3. **Default (`ua`)** — fallback for first-time visitors and SEO crawlers

The user's saved preference **always wins** over URLs shared by others. If a user has `en` in their cookie and clicks a link to `/ua/groups/slug`, they will be redirected to `/en/groups/slug`.

## Implementation files

```text
app/middleware/locale.global.ts    — route middleware (cookie > URL > default)
app/composables/useLocale.ts       — translation composable
app/composables/useLocaleHead.ts   — SEO hreflang composable
app/pages/[locale]/                — all pages live under dynamic [locale] segment
```

## Runtime switching

Locale changes must happen **without a full page reload**.

Use the project's `useLocale()` composable. It updates the cookie, the URL path, and the reactive state in a single call.

Preferred usage:

```js
const { t, locale, setLocale } = useLocale()
```

Example of switching:

```js
setLocale('en')
// Cookie is updated, URL becomes /en/..., state updates reactively
```

## No hardcoded user-facing text

Forbidden:

```vue
<button>Save</button>
```

Required:

```vue
<button>{{ t('common.actions.save') }}</button>
```

This applies to:

- buttons
- labels
- placeholders
- empty states
- errors
- validation messages
- notifications
- modal text
- headings
- emails
- accessibility labels

## Dynamic values

Translation strings may contain interpolation variables using `{variableName}` syntax.

Do not concatenate sentences manually.

Bad:

```js
t('welcome') + user.name
```

Good:

```json
{
  "welcome": "Welcome, {name}!"
}
```

```js
t('welcome', { name: user.name })
```

## Domain values

Never localize values in the domain layer.

Use:

```js
status: 'pending'
```

and translate it at presentation time.

## New keys

When adding a translation key:

1. Add it to `app/locales/ua.json`.
2. Add the same key to `app/locales/en.json`.
3. Keep the key path identical in both files.
4. Do not silently fall back to hardcoded text.

## Adding a new language

To add a new language (e.g., Polish):

1. Create `app/locales/pl.json` with the same key structure as the other files.
2. Add `'pl'` to the `locales` array in `app/middleware/locale.global.ts`.
3. Add `'pl'` to the `Locale` type union in `app/composables/useLocale.ts`.
4. Import and register the new JSON file in `app/composables/useLocale.ts`.
5. Add `'pl'` to the `locales` array in `app/composables/useLocaleHead.ts`.

## SEO and hreflang

Every public page must include hreflang tags via `useLocaleHead()`:

```vue
<script setup lang="ts">
const head = useLocaleHead()
useHead(head)
</script>
```

This generates the required SEO tags:

```html
<link rel="alternate" hreflang="ua" href="https://site.com/ua/path">
<link rel="alternate" hreflang="en" href="https://site.com/en/path">
<link rel="alternate" hreflang="x-default" href="https://site.com/ua/path">
```

The default locale (`ua`) is marked as `x-default` for users without a language preference.

## Persistence

User language preference is stored in a browser cookie named `locale` with a 1-year expiration. This ensures the choice is preserved across sessions and works with server-side rendering (the cookie is sent with every HTTP request, allowing the middleware to resolve the correct locale on the server).

## Translation quality

Translations must preserve meaning, not merely word-for-word structure.

Technical and domain terms should be consistent across the application.
